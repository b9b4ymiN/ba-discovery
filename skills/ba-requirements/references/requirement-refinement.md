# Requirement Refinement

A useful requirement should make the intended outcome and verification boundary clear without prematurely encoding an implementation.

For each material item verify:
- kind: NEED / REQUIREMENT / CONSTRAINT,
- statement and why it matters,
- origin and evidence/derivation,
- status and importance,
- acceptance or verification intent,
- related records and supersession history.

Move DISCOVERED → CLARIFYING → CANDIDATE → CONFIRMED → READY_FOR_DESIGN only when evidence supports the transition. Use NEEDS_RECONFIRMATION when a downstream or upstream change invalidates confidence.
